- TextField 제출 이벤트로 새 단어 검사 시작하기: 입력 뒤 결과가 갱신되는 경로를 메뉴 이름 조합 사례로 추적합니다.

## 핵심 개념 해설

### onAppear에서 첫 문제를 한 번 준비하기

onAppear는 뷰가 화면에 들어올 때 초기 문제를 준비하는 생명주기 지점이며 body 안에서 직접 상태를 바꾸는 일을 피합니다. 값이 만들어지는 지점, 수정 권한을 가진 코드, 최종 소비자를 순서대로 표시해 보세요. 메뉴 이름 조합처럼 익숙한 소재를 사용하면 문법보다 데이터 역할에 집중할 수 있습니다. 컴파일 성공이 도메인 규칙까지 보장하지는 않으므로 경계 입력도 함께 대입해야 합니다.

```swift
@State private var root = "tomato"
@State private var answer = ""
@State private var entries = [String]()

TextField("재료 이름", text: $answer)
    .textInputAutocapitalization(.never)
    .onSubmit { entries.insert(answer.lowercased().trimmingCharacters(in: .whitespaces), at: 0) }
    .onAppear { entries.removeAll() }
```

코드는 원문 예제를 옮기지 않고 메뉴 이름 조합 상황에 맞춰 새로 작성했습니다. 저장된 원본과 계산되는 값, 동작 뒤 바뀌는 값을 구분해 보세요.

### TextField 제출 이벤트로 새 단어 검사 시작하기

정규화한 문자열을 기준으로 중복과 철자를 검사해야 대문자나 앞뒤 공백만 다른 같은 답이 별개로 저장되지 않습니다. 값이 없거나 형식이 틀리거나 범위를 벗어난 경우도 살핍니다. 임의의 기본값이나 강제 언래핑은 실제 원인을 숨길 수 있습니다. 화면 상태는 최소로 저장하고 나머지는 원본에서 계산해야 모순을 예방할 수 있습니다.

리뷰할 때는 값의 소유자, 변경 사건, 실패 뒤 표시를 질문하세요. 오늘의 메뉴 이름 조합 예제에서는 소문자 변환과 공백 제거로 입력 정규화하는 과정이 그 접점입니다. 입력 타입과 출력 타입을 말로 이어 보면 판단 기준을 재사용할 수 있습니다.
