# 11. 실전 UI — UGUI·Safe Area·MVP

> **이 장에서 배울 것**
> - Canvas 렌더 모드와 Canvas Scaler(Scale With Screen Size, Match)로 해상도 대응 원리를 설명할 수 있다
> - RectTransform의 앵커·피벗을 읽고, Layout Group과 캔버스 리빌드 비용을 고려해 UI 계층을 설계할 수 있다
> - `Screen.safeArea`를 적용하는 컴포넌트와 한글 TextMeshPro 폰트 에셋(Dynamic 아틀라스·폴백)을 구성한다
> - 모델·뷰·프레젠터(MVP)로 HUD를 게임 로직과 분리해 구현한다
> - `timeScale = 0` 상태에서도 동작하는 레벨업 선택 창과 게임패드 UI 내비게이션을 구현한다
>
> **선수 장**: 01, 03, 04, 08, 09, 10 · **예상 시간**: 4~5시간 · **코인 러시 진행**: 체력·경험치·타이머·코인 HUD, 업그레이드 3택1 레벨업 창, 결과 화면이 생깁니다

## 왜 필요한가

기초 트랙 STEP 4의 `ScoreDisplay`는 `Update()`에서 매 프레임 `label.text = $"점수: {GameManager.Instance.Score}";`를 실행합니다. 코인 러시가 커지면서 이 방식은 세 군데에서 무너집니다.

1. **성능** — 매 프레임 문자열을 새로 만들고(02장의 GC 할당), 텍스트가 바뀌지 않았는데도 TextMeshPro에 새 문자열을 넣어 메시를 다시 만들게 합니다. 같은 Canvas에 있는 다른 UI까지 다시 그려질 수 있습니다.
2. **해상도** — 에디터의 16:9 Game 뷰에서 좌상단에 맞춘 점수가 아이폰(노치·둥근 모서리)에서는 잘려 보이고, 태블릿에서는 글자가 콩알만 해집니다.
3. **결합도** — `ScoreDisplay`가 `GameManager.Instance`를 직접 읽습니다. 03장에서 싱글턴을 걷어냈는데 UI가 다시 전역 상태에 매달리면, HUD를 테스트 씬에 따로 띄워보는 것조차 어렵습니다.

여기에 레벨업 창이 더해지면 문제가 하나 더 생깁니다. 04장의 `LevelUp` 상태는 `Time.timeScale = 0`으로 게임을 멈춥니다. 그런데 `Time.deltaTime`으로 만든 카드 등장 애니메이션은 **timeScale이 0이면 한 프레임도 진행되지 않습니다.** 게임은 멈췄는데 선택 창도 같이 얼어붙는 것입니다.

이 장에서는 UGUI의 구조를 제대로 이해한 뒤, HUD·레벨업 창·결과 화면을 "싸구려 느낌이 나지 않게" 만듭니다.

## 개념

### UGUI의 구성 요소 한눈에 보기

```
Canvas (루트, 배치 단위) ─ Canvas Scaler(배율) ─ Graphic Raycaster(클릭 판정)
└─ RectTransform 트리: Image·TextMeshProUGUI(그려지는 Graphic), Button·Slider(입력받는 Selectable)
EventSystem (씬에 하나) ─ Input System UI Input Module (입력 → UI 이벤트)
```

웹과 비교하면 Canvas는 `<body>`, RectTransform은 박스 모델, Graphic Raycaster는 hit-test, EventSystem은 이벤트 디스패처입니다. 다만 흐름(flow) 레이아웃이 아니라 **앵커 기반 절대 배치가 기본**입니다.

### Canvas 렌더 모드

- **Screen Space - Overlay**: 모든 카메라가 그린 뒤 맨 위에 덮어 그림. 카메라 불필요. HUD·메뉴 대부분.
- **Screen Space - Camera**: 지정한 카메라 앞 평면에 배치. UI 위에 파티클을 올리거나 후처리를 UI에도 적용할 때.
- **World Space**: 씬 오브젝트처럼 배치. 적 머리 위 체력바, 게임 속 간판.

코인 러시의 HUD·레벨업 창은 **Screen Space - Overlay**로 충분합니다. Overlay 캔버스에는 13장의 Bloom 같은 후처리가 적용되지 않는데, 대개는 이것이 오히려 바람직합니다(글자가 번지지 않음).

### Canvas Scaler — 해상도 대응의 핵심

Canvas Scaler의 **UI Scale Mode**를 `Scale With Screen Size`로 두면, "기준 해상도에서 디자인한 UI를 실제 화면에 맞게 통째로 확대/축소"합니다.

- **Reference Resolution**: 디자인 기준. 가로 게임이면 1920×1080, 세로 모바일 게임이면 1080×1920.
- **Screen Match Mode = Match Width Or Height**, **Match** 슬라이더(0~1):
  - 0이면 가로 폭 기준으로 배율 결정, 1이면 세로 높이 기준.
  - 내부적으로는 두 배율을 로그 공간에서 보간합니다.

```
배율 = 2 ^ lerp( log2(화면W / 기준W), log2(화면H / 기준H), match )
```

예를 들어 기준 1920×1080에서 2532×1170(아이폰 가로) 화면이면 가로 배율 1.319, 세로 배율 1.083입니다. Match 0이면 1.319배로 커져 세로로 넘칠 수 있고, Match 1이면 1.083배로 맞춰져 좌우 여백만 늘어납니다.

**가로 게임은 Match를 1(Height)에 가깝게** 두는 것이 안전합니다. 화면이 옆으로 길어지는 기기(21:9 폰, 울트라와이드 모니터)가 많아서, 높이를 기준으로 삼으면 UI가 위아래로 잘리지 않고 좌우 여백만 늘어납니다. 세로 게임이면 반대로 0(Width)에 가깝게 둡니다.

### RectTransform — 앵커와 피벗

RectTransform의 위치는 "부모 사각형 안의 어느 지점(앵커)에서 얼마나 떨어져 있는가"로 정의됩니다.

```
anchorMin/anchorMax : 부모 기준 정규화 좌표 (0,0)=좌하단, (1,1)=우상단
pivot               : 자기 사각형 안의 기준점. 회전·스케일의 중심
앵커가 한 점  → anchoredPosition + sizeDelta(고정 크기)   예: 우상단 코인 카운터 anchor(1,1) pivot(1,1) pos(-40,-40)
앵커가 벌어짐 → 부모 크기에 따라 늘어남, offsetMin/Max=여백 예: 상단 전체 폭 경험치바 anchorMin(0,1) anchorMax(1,1)
```

Inspector의 앵커 프리셋 창에서 **Alt(Option)** 를 누르고 클릭하면 위치까지, **Shift** 를 누르면 피벗까지 같이 옮겨집니다. 체력바처럼 "왼쪽에서부터 채워지는" UI는 피벗 x를 0으로 두면 스케일 연출이 자연스럽습니다.

> JS: 앵커가 한 점이면 `position:absolute; right:40px; top:40px; width:...`, 앵커가 벌어지면 `left:0; right:0` 처럼 부모에 붙어 늘어나는 박스라고 생각하면 됩니다.

### 캔버스 리빌드 비용과 캔버스 분리

UGUI는 Canvas 하나를 **하나의 묶음 메시**로 만들어 그립니다. 그 안의 Graphic 하나라도 바뀌면(텍스트 변경, 색 변경, 활성/비활성, 위치 이동) 그 Canvas의 배치를 다시 계산합니다. 이를 흔히 **캔버스 리빌드(dirty → rebuild)** 라고 부릅니다.

```
[나쁜 구조]                         [좋은 구조]
Canvas_Main                          Canvas_Main (Overlay)
├─ 배경 프레임 (정적)                  ├─ Canvas_Static   ← 프레임, 아이콘, 라벨
├─ 아이콘 20개 (정적)                  │    (거의 안 바뀜 → 리빌드 거의 없음)
├─ 타이머 텍스트 (매초 변경)            └─ Canvas_Dynamic  ← 타이머, 코인, 게이지
└─ 체력바 (피격마다 변경)                    (자주 바뀜 → 이것만 리빌드)
→ 타이머가 바뀔 때마다 전부 리빌드
```

중첩된 Canvas(자식 GameObject에 Canvas 컴포넌트 추가)는 독립적으로 배치되므로, 자주 바뀌는 것만 따로 모으면 리빌드 범위가 줄어듭니다. 단, 캔버스를 너무 잘게 쪼개면 드로우 콜이 늘어나므로 **"정적 / 자주 변함 / 팝업"** 정도로 나누는 것이 현실적입니다. 자식 Canvas에는 Graphic Raycaster가 필요할 때만 붙이세요.

추가로 알아둘 비용:

- **Raycast Target**: Image·Text의 기본값이 켜져 있습니다. 클릭받지 않는 장식·텍스트는 꺼야 Graphic Raycaster의 판정 대상이 줄어듭니다.
- **UI를 숨길 때**: `SetActive(false)` 후 다시 켜면 레이아웃·리빌드가 일어납니다. 자주 여닫는 팝업은 CanvasGroup(alpha 0, interactable·blocksRaycasts false)이나 팝업 Canvas의 `enabled`로 숨기는 편이 가볍습니다.

### Layout Group과 Content Size Fitter

`Horizontal/Vertical/Grid Layout Group`(자식 자동 배치)과 `Content Size Fitter`(내용물에 맞춰 크기 조절)는 flexbox처럼 편하지만, 자식이 추가·제거되거나 크기가 바뀔 때마다 계층을 따라 레이아웃을 재계산합니다. 중첩된 Layout Group, 길이가 매 프레임 바뀌는 텍스트, 수백 개 항목 리스트에서 비용이 커집니다. **원칙**: "열릴 때 한 번" 배치하는 곳(레벨업 카드 3장, 설정 메뉴)에는 쓰고, **매 프레임 값이 바뀌는 HUD는 앵커로 고정 배치**합니다.

### Safe Area — 노치와 둥근 모서리

`Screen.safeArea`는 **픽셀 단위의 Rect**로, 노치·홈 인디케이터·펀치홀을 피한 "안전하게 그릴 수 있는 영역"을 알려줍니다. 이 Rect를 화면 크기로 나눠 정규화하면 RectTransform의 앵커로 그대로 쓸 수 있습니다.

그래서 `Canvas → SafeArea(앵커를 safeArea로 맞춤) → HUD 요소들` 구조로 잡고, 화면 끝까지 채워야 하는 배경·딤(dim)은 SafeArea 밖(Canvas 직속)에 둡니다.

에디터에서는 **Window → General → Device Simulator**로 기기를 골라 Safe Area를 확인할 수 있습니다. Game 뷰 상단 드롭다운에서 Game ↔ Simulator를 전환합니다.

### TextMeshPro와 한글 폰트 에셋

TextMeshPro(TMP)는 폰트를 **SDF(Signed Distance Field) 텍스처 아틀라스**로 구워서 그립니다. 영어는 100자 안팎이면 되지만, 한글 완성형은 11,172자이고 일상적으로 쓰는 글자(KS X 1001)만 해도 2,350자입니다. 기본 제공 폰트(LiberationSans SDF)에는 한글이 없어 □(두부)로 나옵니다.

폰트 에셋의 **Atlas Population Mode** 두 가지:

| 모드 | 동작 | 장점 | 단점 |
|---|---|---|---|
| Static | Font Asset Creator로 지정한 글자만 미리 굽기 | 런타임 비용 없음, 결과 예측 가능 | 목록에 없는 글자는 표시 안 됨 |
| Dynamic | 처음 등장한 글자를 런타임에 아틀라스에 추가 | 모든 글자 대응 | 원본 폰트 파일(.ttf/.otf)이 빌드에 포함됨, 첫 등장 시 약간의 비용, 에디터에서 에셋이 계속 변경되어 git diff 발생 |

실전 구성은 **"정적 기본 + 동적 폴백"** 입니다. `Pretendard SDF (Static: 영문·숫자·기호 + KS X 1001 2,350자)`의 Fallback 목록에 `Pretendard Dynamic`을 넣어, 닉네임 등 예상 못 한 글자만 동적 아틀라스로 보냅니다. TMP는 글자를 메인 폰트에서 찾지 못하면 **Fallback Font Assets 목록**을 순서대로 뒤지고, 그래도 없으면 TMP Settings의 전역 Fallback 목록을 봅니다. 폰트 라이선스는 반드시 확인하세요. Pretendard, Noto Sans KR은 SIL Open Font License로 게임 포함 배포가 가능합니다(라이선스 파일 동봉 조건은 원문 확인).

아틀라스 설정은 Sampling Point Size 40~60(한글은 획이 많아 너무 작으면 뭉개짐), Padding은 외곽선·그림자를 쓸 거면 샘플 크기의 10% 안팎, 해상도는 2,350자를 48pt로 담으려면 4096 한 장 수준입니다. 모바일 메모리를 생각해 Dynamic 쪽은 Multi Atlas Textures로 2048을 여러 장 쓰는 편이 안전합니다.

### MVP — 게임 로직과 UI 분리

```
 Model (게임 로직)              Presenter (연결)               View (표시만)
 ┌──────────────┐  이벤트     ┌──────────────────┐  메서드    ┌─────────────┐
 │ Health       │───────────▶│ HudPresenter     │──────────▶│ HudView     │
 │ PlayerExp    │  Changed    │ - 구독/해제       │ SetHealth │ - Image     │
 │ coin 채널    │             │ - 값 가공(비율,  │ SetTimer  │ - TMP 텍스트│
 └──────────────┘             │   포맷)          │ ...       └─────────────┘
        ▲                     └──────────────────┘                 │
        └──────── (사용자 입력이 있으면 Presenter가 모델 호출) ◀──────┘
```

View는 "체력 비율 0.4를 보여줘" 같은 명령만 받고 `Health`를 모릅니다. Model은 UI를 모르고 이벤트만 발행합니다. Presenter가 둘을 잇고, 구독은 `OnEnable`·해제는 `OnDisable`에서 짝을 맞춥니다. React로 치면 Model은 store, View는 props만 받는 presentational component, Presenter는 store를 구독해 props를 내려주는 container component입니다.

### UGUI와 UI Toolkit — 언제 무엇을

기초 트랙 STEP 1~3에서 UI Toolkit을, STEP 4에서 UGUI를 맛봤습니다. Unity 6 기준 선택표입니다.

| 기준 | UGUI | UI Toolkit |
|---|---|---|
| 작성 방식 | GameObject + 컴포넌트, 씬/프리팹 편집 | UXML(구조) + USS(스타일) + C#, 웹과 유사 |
| 레이아웃 | 앵커 기반 절대 배치 (+Layout Group) | Flexbox (Yoga 엔진) |
| 게임 오브젝트와 섞기 | 쉬움 (World Space, 파티클, Animator) | 제한적 (월드 공간 UI 지원은 버전별로 확인) |
| 셰이더·후처리 연동 | 머티리얼 교체 가능 | 제한적 |
| 에디터 툴(20장) | 부적합 | 표준 |
| 추천 용도 | 인게임 HUD, 연출 많은 팝업 | 설정·인벤토리 등 폼 형태 메뉴, 에디터 확장 |

코인 러시는 **인게임은 UGUI**로 통일합니다. 연출(스케일 튕김, 파티클)이 많고, 13~16장의 효과와 섞기 쉽기 때문입니다. 한 화면 안에서 두 시스템을 섞는 것은 입력 처리와 정렬 순서가 복잡해지므로 피하세요.

### EventSystem과 게임패드 내비게이션

Unity 6 신규 프로젝트는 Input System 패키지를 쓰므로, EventSystem에는 **Input System UI Input Module**이 붙어 있어야 합니다(구형 Standalone Input Module이 있으면 Inspector의 교체 버튼을 누르세요). 이 모듈이 08장에서 본 액션 에셋의 UI 액션맵(Navigate, Submit, Cancel, Point, Click)을 읽습니다.

게임패드로 UI를 조작하려면:

1. **Selectable**의 `Navigation`이 이웃을 정합니다. `Automatic`은 배치를 보고 추정, `Explicit`은 직접 지정. Inspector의 **Visualize** 버튼으로 연결을 화살표로 볼 수 있습니다.
2. EventSystem의 `First Selected`는 씬 시작 때만 쓰이므로, **팝업을 열 때마다** `EventSystem.current.SetSelectedGameObject(버튼)`을 호출해야 패드 입력이 갈 곳이 생깁니다.
3. 선택 상태가 **눈에 보여야** 합니다. Button Transition의 Selected Color를 확실히 다르게 주거나 스케일을 키웁니다.

## 실습: 코인 러시에 적용하기

이 실습에서 앞 장의 클래스를 사용합니다. 파일이 없거나 멤버 이름이 다르면 아래 최소 시그니처에 맞춰 조정하세요.

```csharp
// 01장 Health          : int Current, int Max, event Action<int,int> Changed(current,max), event Action Died, TakeDamage(int)
// 03장 IntEventChannel : event Action<int> OnRaised, void Raise(int)  — 여기서는 "획득한 코인 증가분"을 보냄
// 04장 상태 머신        : interface IGameState { void Enter(); void Tick(); void Exit(); }, GameStateMachine.ChangeState(IGameState),
//                        PlayingState.ElapsedTime(Playing에서만 증가), ScoreKeeper.Score, Health.Heal(int)/Initialize(int)
// 08장 ControlsManager : static Instance, UseGameplay(), UseUI()  — 09장부터 Bootstrap 씬에 있음
```

### 1단계 — Canvas 골격 만들기

1. Hierarchy → UI → Canvas. 이름 `HUDCanvas`, Render Mode `Screen Space - Overlay`.

```csharp
using UnityEngine;

[RequireComponent(typeof(RectTransform))]
public class SafeAreaFitter : MonoBehaviour
{
    private RectTransform rectTransform;
    private Rect lastSafeArea;
    private Vector2Int lastScreenSize;

    private void Awake() => rectTransform = GetComponent<RectTransform>();
    private void OnEnable() => Apply();

    private void Update()
    {
        // 회전·분할 화면·해상도 변경 시 safeArea가 바뀝니다. 값 비교만 하므로 할당 없음.

    {
        Rect safe = Screen.safeArea;
        lastSafeArea = safe;
        lastScreenSize = new Vector2Int(Screen.width, Screen.height);
        if (Screen.width <= 0 || Screen.height <= 0) return;

        var size = new Vector2(Screen.width, Screen.height);
        rectTransform.anchorMin = safe.position / size;           // 성분별 나눗셈
        rectTransform.anchorMax = (safe.position + safe.size) / size;
        rectTransform.offsetMin = Vector2.zero;
        rectTransform.offsetMax = Vector2.zero;
    }
```

### 3단계 — 한글 폰트 에셋

### 4단계 — 모델: 경험치

체력은 01장의 `Health`를 그대로 씁니다. 경험치 모델이 아직 없다면 만듭니다.

```csharp
// Assets/_CoinRush/Scripts/Player/PlayerExperience.cs
using System;
using UnityEngine;

public class PlayerExperience : MonoBehaviour
{
    [SerializeField] private int baseRequired = 5;
    [SerializeField] private float growth = 1.25f;

    public int Level { get; private set; } = 1;
    public int Current { get; private set; }
    public int Required { get; private set; }

    public event Action<int, int> Changed;   // (current, required)
    public event Action<int> LeveledUp;      // 새 레벨 — 04장 LevelUp 상태 진입 트리거

    private void Awake() => Required = CalcRequired(Level);

    public void Add(int amount)
    {
        if (amount <= 0) return;
        Current += amount;

        // 한 번에 많이 먹어도 레벨업은 한 단계씩 처리합니다. 남은 경험치는 다음 레벨로 이월.
        if (Current >= Required)
        {
            Current -= Required;
            Level++;
            Required = CalcRequired(Level);
            Changed?.Invoke(Current, Required);
            LeveledUp?.Invoke(Level);
        }
        else Changed?.Invoke(Current, Required);
    }

    private int CalcRequired(int level) => Mathf.RoundToInt(baseRequired * Mathf.Pow(growth, level - 1));
}
```

> 한 번에 두 단계 이상 넘치는 경우는 연습 문제 3에서 다룹니다. 성장 곡선 수치는 23장에서 다시 설계합니다.

```csharp
        coinText.SetText("{0}", coins);
        if (punch) coinPunch = 1f;
    }

    private void Update()
    {
        // 코인 아이콘 펀치: 1.3배 → 1배
        if (coinPunch > 0f && coinIcon != null)
        {
            coinPunch = Mathf.Max(0f, coinPunch - Time.unscaledDeltaTime * 6f);
            float s = 1f + 0.3f * coinPunch * coinPunch;
            coinIcon.localScale = new Vector3(s, s, 1f);
        }
    }
```

```csharp
// Assets/_CoinRush/Scripts/UI/HudPresenter.cs
using UnityEngine;

public class HudPresenter : MonoBehaviour
{
    [SerializeField] private HudView view;
    [SerializeField] private Health playerHealth;
    [SerializeField] private PlayerExperience playerExperience;
    [SerializeField] private IntEventChannel coinCollectedChannel;
    [SerializeField] private GameStateMachine stateMachine;   // 04장 — 판 시간의 주인은 PlayingState

    private int coins;

    private void OnEnable()
    {
        playerHealth.Changed += OnHealthChanged;
        playerExperience.Changed += OnExperienceChanged;
        coinCollectedChannel.OnRaised += OnCoinCollected;

        // 구독 직후 현재 값으로 한 번 그려줍니다 (이벤트가 오기 전까지 빈 화면 방지)
        OnHealthChanged(playerHealth.Current, playerHealth.Max);
        OnExperienceChanged(playerExperience.Current, playerExperience.Required);
        view.SetCoins(coins, false);
    }

    private void OnDisable()
    {
        playerHealth.Changed -= OnHealthChanged;
        playerExperience.Changed -= OnExperienceChanged;
        coinCollectedChannel.OnRaised -= OnCoinCollected;
    }

    private void Update()
    {
        // 시간을 따로 누적하지 않고 04장 PlayingState.ElapsedTime을 표시만 합니다.
        // Playing에서만 증가하므로 LevelUp·Result 중에는 멈추고, 결과 화면 기록과도 항상 같습니다.
        if (stateMachine.Playing != null) view.SetTimer(stateMachine.Playing.ElapsedTime);
    }

    private void OnHealthChanged(int current, int max)
        => view.SetHealth(max > 0 ? (float)current / max : 0f);

    private void OnExperienceChanged(int current, int required)
        => view.SetExperience(required > 0 ? (float)current / required : 0f, playerExperience.Level);

    private void OnCoinCollected(int amount) => view.SetCoins(coins += amount, true);
}
```

```csharp
using UnityEngine;
using UnityEngine.EventSystems;

public class ButtonPunch : MonoBehaviour,
    IPointerDownHandler, IPointerUpHandler, IPointerExitHandler, ISelectHandler, IDeselectHandler
{
    [SerializeField] private float pressedScale = 0.92f;
    [SerializeField] private float selectedScale = 1.06f;
    [SerializeField] private float speed = 18f;

    private float target = 1f;
    private float velocity;
    private bool selected;

    public void OnPointerDown(PointerEventData e) => target = pressedScale;
    public void OnPointerUp(PointerEventData e) => target = selected ? selectedScale : 1f;
    public void OnPointerExit(PointerEventData e) => target = selected ? selectedScale : 1f;
    public void OnSelect(BaseEventData e) { selected = true; target = selectedScale; }
    public void OnDeselect(BaseEventData e) { selected = false; target = 1f; }

    private void OnDisable()
    {
        transform.localScale = Vector3.one;
        velocity = 0f; selected = false; target = 1f;
    }

    private void Update()
    {
        // 감쇠 스프링 — 목표를 살짝 지나쳤다 돌아오며 "탱" 하는 느낌. unscaled라 일시정지 중에도 동작
        float dt = Time.unscaledDeltaTime;
        float s = transform.localScale.x;
        velocity += (target - s) * speed * speed * dt;
        velocity *= Mathf.Exp(-speed * 0.9f * dt);
        s += velocity * dt;
        transform.localScale = new Vector3(s, s, 1f);
    }
```

패널 본체입니다. `Time.timeScale = 0`에서 동작하도록 **코루틴 + `unscaledDeltaTime`** 을 씁니다. 코루틴의 `yield return null`은 timeScale과 무관하게 다음 프레임에 재개되지만, `WaitForSeconds`는 멈춘다는 점에 주의하세요(대신 `WaitForSecondsRealtime`).

```csharp
// Assets/_CoinRush/Scripts/UI/LevelUpPanel.cs
using System;
using System.Collections;
using UnityEngine;
using UnityEngine.EventSystems;

[RequireComponent(typeof(CanvasGroup))]
public class LevelUpPanel : MonoBehaviour
{
    [SerializeField] private UpgradeCardView[] cards = new UpgradeCardView[3];
    [SerializeField] private float fadeDuration = 0.15f;
    [SerializeField] private float cardDuration = 0.35f;
    [SerializeField] private float cardStagger = 0.08f;

    private CanvasGroup group;
    private Action<UpgradeData> onChosen;
    private bool choosing;

    private void Awake() { group = GetComponent<CanvasGroup>(); HideImmediate(); }

    public void Show(UpgradeData[] options, Action<UpgradeData> chosenCallback)
    {
        onChosen = chosenCallback;
        choosing = false;

        for (int i = 0; i < cards.Length; i++)
        {
            bool has = i < options.Length && options[i] != null;
            cards[i].gameObject.SetActive(has);
            if (!has) continue;

            UpgradeData data = options[i];
            cards[i].Bind(data, () => Choose(data));
            cards[i].Rect.localScale = Vector3.zero;
        }

        group.alpha = 0f;
        group.interactable = false;   // 등장 연출 중 실수 클릭 방지
        group.blocksRaycasts = true;
        StopAllCoroutines();
        StartCoroutine(ShowRoutine());
    }

    private IEnumerator ShowRoutine()
    {
        float t = 0f;
        float total = fadeDuration + cardStagger * (cards.Length - 1) + cardDuration;

        while (t < total)
        {
            t += Time.unscaledDeltaTime;
            group.alpha = Mathf.Clamp01(t / fadeDuration);

            for (int i = 0; i < cards.Length; i++)
            {
                float local = (t - fadeDuration - cardStagger * i) / cardDuration;
                float s = EaseOutBack(Mathf.Clamp01(local));
                cards[i].Rect.localScale = new Vector3(s, s, 1f);
            }
            yield return null;
        }

        group.interactable = true;
        // 게임패드 사용자를 위해 가운데 카드를 선택 (카드가 하나뿐이면 첫 카드)
        UpgradeCardView first = cards.Length > 1 && cards[1].gameObject.activeSelf ? cards[1] : cards[0];
        EventSystem.current.SetSelectedGameObject(first.Button.gameObject);
    }

    private void Choose(UpgradeData data)
    {
        if (choosing) return;          // 같은 프레임 더블클릭·패드 연타 방지
        choosing = true;
        HideImmediate();
        onChosen?.Invoke(data);
    }

    private void HideImmediate()
    {
        group.alpha = 0f;
        group.interactable = group.blocksRaycasts = false;
        if (EventSystem.current != null) EventSystem.current.SetSelectedGameObject(null);
    }

    // 06장의 이징 — 목표를 살짝 넘었다 돌아옴 (c1 = 1.70158)
    private static float EaseOutBack(float x)
    {
        float p = x - 1f;
        return 1f + 2.70158f * p * p * p + 1.70158f * p * p;
    }
}
```

에디터 구성:

1. Hierarchy → UI → Canvas, 이름 `PopupCanvas`. Scaler 설정은 HUDCanvas와 동일, **Sort Order 10**(HUD보다 위). Graphic Raycaster 유지.
2. 그 아래 `LevelUpPanel`(stretch-stretch) + `CanvasGroup` + `LevelUpPanel` 스크립트. 자식으로 반투명 검정 Image `Dim`(stretch, 알파 0.6).
3. `Dim` 위에 `SafeArea`(SafeAreaFitter) → 그 아래 `Cards`(Horizontal Layout Group, Spacing 48, Child Alignment Middle Center, Control Child Size 끔).
4. 카드 프리팹은 **2단 구조**로 만듭니다. 루트 `Card`(RectTransform 420×560 + `UpgradeCardView`) → 자식 `Body`(stretch, Image 배경 + Button + `ButtonPunch`) → 그 아래 아이콘·제목·설명. 패널의 등장 스케일은 루트에, `ButtonPunch`의 눌림 스케일은 `Body`에 걸려서 두 연출이 같은 `localScale`을 두고 싸우지 않습니다. 3개 배치 후 `cards` 배열에 연결합니다.
5. `Body` Button의 Transition Selected Color를 밝은 노랑으로 바꿔, 패드로 선택된 카드가 확실히 보이게 합니다.

> Horizontal Layout Group은 패널이 열릴 때 배치만 하면 되므로 여기서는 써도 됩니다. 카드 스케일 연출은 `localScale`만 바꾸므로 레이아웃을 다시 계산시키지 않습니다(레이아웃은 스케일을 무시함).

### 9단계 — 04장 LevelUp 상태와 연결

04장의 `LevelUpState`가 진입할 때 패널을 열고, 선택이 끝나면 효과를 적용한 뒤 Playing으로 돌아가게 합니다. 04장 파일 전체를 아래로 교체합니다.

입력 맵도 여기서 바꿉니다. 08장 `ControlsManager.UseGameplay()`는 UI 맵을 끄므로, 레벨업 창이 열려 있는 동안에는 `UseUI()`로 바꿔야 패드·마우스로 카드를 고를 수 있습니다. 또 Gameplay 맵(일시정지 액션 포함)이 꺼지므로 레벨업 중에는 Pause 액션 자체가 발생하지 않고, 08장 `PauseController.Pause`도 `Current != Playing`이면 들어가지 않습니다(모바일 Pause 버튼 대비). UI/Cancel은 켜져 있지만 `PauseController.Resume`은 `IsPaused`가 아니면 아무것도 하지 않으므로 `timeScale`을 1로 되돌리지 않습니다. 즉 **일시정지는 Playing에서만** 들어갈 수 있고, `timeScale`과 입력 맵의 주인은 한 시점에 하나의 상태입니다.

```csharp
// Assets/_CoinRush/Scripts/Core/GameStates/LevelUpState.cs (04장 파일 교체)
using UnityEngine;

public class LevelUpState : IGameState
{
    private readonly GameStateMachine machine;
    private readonly IGameState playingState;
    private readonly LevelUpPanel panel;
    private readonly UpgradeData[] pool;
    private readonly UpgradeData[] picks = new UpgradeData[3];

    public LevelUpState(GameStateMachine machine, IGameState playingState,
                        LevelUpPanel panel, UpgradeData[] pool)
    {
        this.machine = machine;
        this.playingState = playingState;
        this.panel = panel;
        this.pool = pool;
    }

    public void Enter()
    {
        Time.timeScale = 0f;
        machine.SetGameplayActive(false);                          // 04장과 같음: 무기·스포너·이동 입력 끄기
        if (machine.Controls != null) machine.Controls.UseUI();   // 카드 조작은 UI 맵, 일시정지 액션은 꺼짐
        PickThree();
        panel.Show(picks, OnChosen);
    }

    public void Tick() { }

    public void Exit()
    {
        if (machine.Controls != null) machine.Controls.UseGameplay();
        Time.timeScale = 1f;   // 반드시 복구 (04장 함정 3)
    }

    private void OnChosen(UpgradeData chosen)
    {
        if (machine.Current != this) return;          // 이미 다른 상태로 넘어갔으면 무시 (버튼 연타 방어)
        chosen.Apply(machine.PlayerHealth);            // 04장 Apply(int)를 데이터 기반으로 대체
        machine.ChangeState(playingState);
    }

    private void PickThree()
    {
        // 부분 Fisher–Yates (06장): 앞 3칸만 섞어 중복 없이 뽑기. 원본 배열은 건드리지 않음.
        var temp = (UpgradeData[])pool.Clone();
        for (int i = 0; i < picks.Length; i++)
        {
            if (i >= temp.Length) { picks[i] = null; continue; }
            int j = Random.Range(i, temp.Length);
            (temp[i], temp[j]) = (temp[j], temp[i]);
            picks[i] = temp[i];
        }
    }
}
```

`Clone()`은 레벨업마다 작은 배열을 하나 할당하지만, 레벨업은 드문 이벤트이므로 괜찮습니다.

생성자가 바뀌었으므로 04장 `GameStateMachine`도 함께 고칩니다. 04장의 GameObject 기반 UI 필드(`levelUpPanel`, `levelUpLabel`, `resultPanel`, `resultLabel`)와 그 프로퍼티·`Awake`의 `SetActive(false)` 두 줄, `ChooseUpgrade` 메서드는 **삭제**하고 아래를 추가·교체합니다. 10단계의 결과 화면 필드도 여기서 함께 넣습니다(`ResultView` 클래스는 10단계에서 만들므로, 10단계까지 작성한 뒤 컴파일 오류가 사라집니다).

### 10단계 — 결과 화면

```csharp
// Assets/_CoinRush/Scripts/UI/ResultView.cs
using TMPro;
using UnityEngine;
using UnityEngine.EventSystems;
using UnityEngine.UI;

[RequireComponent(typeof(CanvasGroup))]
public class ResultView : MonoBehaviour
{
    [SerializeField] private TMP_Text titleText;
    [SerializeField] private TMP_Text timeText;
    [SerializeField] private TMP_Text coinText;
    [SerializeField] private Button retryButton;
    [SerializeField] private Button titleButton;
    [SerializeField] private float countUpDuration = 0.8f;

    [Header("09장 이벤트 채널 — Bootstrap의 GameFlow가 씬을 전환")]
    [SerializeField] private VoidEventChannel retryRequested;
    [SerializeField] private VoidEventChannel returnToTitleRequested;

    private CanvasGroup group;
    private bool requested;   // 버튼 연타로 채널이 두 번 발행되지 않게

    private void Awake()
    {
        group = GetComponent<CanvasGroup>();
        retryButton.onClick.AddListener(OnRetry);
        titleButton.onClick.AddListener(OnTitle);
        SetVisible(false);
    }

    private void OnRetry()  { if (Consume()) retryRequested.Raise(); }          // GameFlow.Retry → Game 씬 다시 로드
    private void OnTitle()  { if (Consume()) returnToTitleRequested.Raise(); }  // GameFlow.GoToTitle → Title 씬

    private bool Consume()
    {
        if (requested) return false;
        requested = true;
        group.interactable = false;
        return true;
    }

    public void Show(bool cleared, float survivedSeconds, int coins)
    {
        titleText.text = cleared ? "생존 성공!" : "쓰러졌습니다";
        int total = Mathf.FloorToInt(survivedSeconds);
        timeText.text = $"생존 시간 {total / 60:00}:{total % 60:00}";
        requested = false;
        SetVisible(true);

        StopAllCoroutines();
        StartCoroutine(CountUp(coins));
        EventSystem.current.SetSelectedGameObject(retryButton.gameObject);
    }

    private System.Collections.IEnumerator CountUp(int target)
    {
        // 숫자 카운트업: 결과 화면이 "보상받는 느낌"을 주는 가장 싼 연출
        float t = 0f;
        while (t < countUpDuration)
        {
            t += Time.unscaledDeltaTime;
            float p = 1f - Mathf.Pow(1f - Mathf.Clamp01(t / countUpDuration), 3f);
            coinText.SetText("획득 코인 {0}", Mathf.RoundToInt(target * p));
            yield return null;
        }
        coinText.SetText("획득 코인 {0}", target);
    }

    private void SetVisible(bool visible)
    {
        group.alpha = visible ? 1f : 0f;
        group.interactable = group.blocksRaycasts = visible;
    }
}
```

버튼은 게임 씬 안의 상태를 바꾸지 않고 09장 채널만 발행합니다. 09장에서 Title은 **별도 씬**이고 재시작은 Game 씬을 다시 로드하는 일이므로, 둘 다 Bootstrap의 `GameFlow`가 맡습니다(Game 씬의 `TitleState`로 가는 것이 아닙니다).

## 흔한 실수

1. **레벨업 창이 안 움직이고 멈춰 있음** → `Time.deltaTime`, `WaitForSeconds`, Animator 기본 Update Mode는 timeScale 0에서 진행하지 않음 → `Time.unscaledDeltaTime`, `WaitForSecondsRealtime`, Animator Update Mode `Unscaled Time`으로 바꿉니다.
2. **게임패드로 UI가 조작되지 않음** → 선택된 오브젝트가 없거나, EventSystem에 구형 Standalone Input Module이 붙어 있거나, 08장 `ControlsManager`가 UI 맵을 꺼 둔 상태 → 모듈을 Input System UI Input Module로 교체하고, 팝업이 열릴 때 `SetSelectedGameObject`를 호출하며, 팝업 상태의 Enter/Exit에서 `UseUI()`/`UseGameplay()`를 짝지어 호출합니다.
3. **한글이 □로 나오거나 일부 글자만 빠짐** → 기본 폰트 사용, 또는 Static 아틀라스에 해당 글자가 없고 폴백이 없음 → Static + Dynamic 폴백 구성을 하고 TMP Settings의 기본 폰트를 바꿉니다. 콘솔의 "character ... was not found" 경고를 확인하세요.
4. **HUD 뒤의 게임 오브젝트를 클릭할 수 없음 / 버튼이 클릭 안 됨** → 투명한 Image나 텍스트의 Raycast Target이 켜져 입력을 가로챔, 또는 숨긴 패널의 `blocksRaycasts`가 true → 장식의 Raycast Target을 끄고 숨길 때 CanvasGroup 세 값을 함께 바꿉니다.
5. **이벤트 구독 누수로 씬 재시작 후 MissingReferenceException** → `OnEnable`에서 구독하고 `OnDisable`에서 해제하지 않음, 또는 람다로 구독해 해제 불가 → 메서드 그룹으로 구독·해제 짝을 맞춥니다(01장).
6. **태블릿·울트라와이드에서 UI가 잘림** → Canvas Scaler가 Constant Pixel Size이거나 Match가 게임 방향과 반대 → Scale With Screen Size, 가로 게임은 Match 1 근처로 설정하고 Game 뷰에서 여러 비율로 확인합니다.

<details><summary>힌트·해설</summary>

`displayed`(float)와 `target`(int)을 두고 `Update`에서 `Mathf.MoveTowards(displayed, target, speed * Time.unscaledDeltaTime)`로 따라가게 합니다. 속도는 `Mathf.Max(1, 차이) / 0.3f`로 차이에 비례시키면 큰 값도 0.3초 안에 도착합니다. `int shown = Mathf.RoundToInt(displayed)`가 직전과 다를 때만 `SetText`를 호출하세요.

</details>

3. ★★☆ `PlayerExperience`가 한 번에 두 레벨 이상을 넘겼을 때, 레벨업 창이 연속으로 뜨도록 만드세요.

<details><summary>힌트·해설</summary>

`PlayerExperience`에 `public bool TryConsumeLevelUp()` 같은 메서드를 두어 `Current >= Required`이면 레벨을 올리고 true를 반환하게 합니다. `LevelUpState.OnChosen`에서 `chosen.Apply(...)` 뒤 바로 Playing으로 가지 말고, `TryConsumeLevelUp()`이 true면 패널을 다시 `Show`합니다. `LeveledUp` 이벤트가 상태 전환 도중에 다시 발생해 `ChangeState`가 중첩 호출되지 않도록, 이벤트 발행과 상태 전환 순서를 명확히 하는 것이 핵심입니다.

</details>

4. ★★★ 설정 화면을 UI Toolkit으로, 인게임 HUD는 UGUI로 만든 뒤 두 시스템이 한 화면에 떠 있을 때 게임패드 포커스가 어디로 가는지 조사하고, 둘 중 하나만 입력을 받도록 전환하는 구조를 설계·구현하세요.

<details><summary>힌트·해설</summary>

UI Toolkit은 `UIDocument`와 `PanelSettings`(Sort Order)로 그려지고, 포커스는 `VisualElement.Focus()`로 관리됩니다. UGUI의 EventSystem과는 포커스 개념이 다르므로, "지금 입력 주인이 누구인가"를 한 곳(예: 상태 머신의 상태)이 결정하게 하고, UGUI 쪽은 `EventSystem.current.SetSelectedGameObject(null)` + CanvasGroup 비활성, UI Toolkit 쪽은 루트 요소의 `SetEnabled(false)` 등으로 끄는 식입니다. 조사 결과를 표로 정리하고, 본인의 결론(섞을 것인가 통일할 것인가)을 한 문단으로 쓰세요.

</details>

## 셀프 체크

1. 타이머 텍스트와 정적 프레임을 같은 Canvas에 두면 왜 비효율적인지, 어떻게 고치는지 설명해보세요.

<details><summary>모범 답안</summary>

UGUI는 Canvas 단위로 메시를 묶어 만들고, 그 안의 Graphic 하나가 바뀌면 캔버스 배치를 다시 계산합니다. 타이머가 바뀔 때마다 변하지 않는 프레임과 아이콘까지 다시 계산되는 셈입니다. 자주 바뀌는 요소를 자식 Canvas로 분리하면 리빌드가 그 캔버스에 한정됩니다. 추가로 값이 실제로 바뀔 때만 텍스트를 설정해 리빌드 횟수 자체를 줄입니다.

</details>

2. 한글 TMP 폰트를 Static 기본 + Dynamic 폴백으로 구성하는 이유를 두 모드의 장단점으로 설명해보세요.

<details><summary>모범 답안</summary>

Static은 미리 구운 글자만 있어 런타임 비용이 없고 결과가 예측 가능하지만, 목록에 없는 글자(희귀 한자, 사용자 입력)는 표시하지 못합니다. Dynamic은 모든 글자를 처리하지만 원본 폰트가 빌드에 포함되고 첫 등장 시 굽는 비용이 있으며 에디터에서 에셋이 계속 변경됩니다. 자주 쓰는 2,350자는 Static으로 처리하고 빠진 글자만 Dynamic으로 넘기면 두 장점을 함께 얻습니다.

</details>

3. MVP에서 `HudView`가 `Health`를 직접 참조하지 않게 했을 때 얻는 이점 두 가지를 말해보세요.

<details><summary>모범 답안</summary>

첫째, View를 교체하거나 디자인을 크게 바꿔도 모델과 프레젠터가 영향을 받지 않습니다. 둘째, View만 테스트 씬에 두고 `SetHealth(0.3f)` 같은 호출로 모든 상태를 눈으로 확인할 수 있고, 반대로 모델은 UI 없이 동작합니다. 구독·해제 책임이 Presenter 한 곳에 모여 누수를 찾기도 쉽습니다.

</details>

4. timeScale이 0일 때 코루틴의 `yield return null`, `WaitForSeconds`, `WaitForSecondsRealtime`은 각각 어떻게 동작하나요?

<details><summary>모범 답안</summary>

`yield return null`은 timeScale과 무관하게 다음 프레임에 재개됩니다. `WaitForSeconds`는 스케일된 시간을 기다리므로 timeScale 0에서는 끝나지 않습니다. `WaitForSecondsRealtime`은 실제 시간을 기다리므로 정상 동작합니다. 그래서 일시정지 중 UI 애니메이션은 `yield return null` 루프 안에서 `Time.unscaledDeltaTime`을 누적하거나 `WaitForSecondsRealtime`을 씁니다.

</details>

## 핵심 요약

- Canvas Scaler는 `Scale With Screen Size` + 기준 해상도 + Match(가로 게임은 1 근처)로 설정합니다.
- RectTransform은 앵커(부모 기준 위치)와 피벗(자기 기준점)으로 배치하며, HUD는 앵커 고정, 가변 목록만 Layout Group을 씁니다.
- 자주 바뀌는 UI는 별도 Canvas로 분리하고, 값이 실제로 바뀔 때만 갱신해 리빌드를 줄입니다. 클릭받지 않는 Graphic은 Raycast Target을 끕니다.
- 한글은 Static(2,350자) 폰트 에셋 + Dynamic 폴백으로 구성하고, `SafeAreaFitter`로 노치를 피합니다.
- Model(Health, PlayerExperience) – Presenter(구독·가공) – View(표시·연출)로 나누면 UI와 로직이 서로를 모릅니다.
- 일시정지 중 UI는 `unscaledDeltaTime`/`WaitForSecondsRealtime`/Animator Unscaled Time으로 움직입니다.
- 게임패드 UI는 Input System UI Input Module, Selectable Navigation, 팝업마다 `SetSelectedGameObject`가 필수입니다.
