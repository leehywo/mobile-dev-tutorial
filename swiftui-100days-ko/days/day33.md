# Day 33 — 제스처와 전환 애니메이션

## 오늘 배우는 것

- DragGesture의 translation을 화면 위치에 연결하기: 엽서 넘기기의 담당 값을 코드에서 찾습니다.
- gesture 종료 뒤 spring으로 카드 원위치시키기: 입력 뒤 결과가 갱신되는 경로를 엽서 넘기기 사례로 추적합니다.
- transition으로 뷰 삽입과 제거의 움직임 정하기: 문법 뒤에 경계 조건이 숨지 않는지 점검합니다.

## 핵심 개념 해설

### DragGesture의 translation을 화면 위치에 연결하기

translation은 제스처가 시작된 지점부터의 이동량이므로 카드의 원래 좌표를 잃지 않고 offset에 적용할 수 있습니다. 값이 만들어지는 지점, 수정 권한을 가진 코드, 최종 소비자를 순서대로 표시해 보세요. 엽서 넘기기처럼 익숙한 소재를 사용하면 문법보다 데이터 역할에 집중할 수 있습니다. 컴파일 성공이 도메인 규칙까지 보장하지는 않으므로 경계 입력도 함께 대입해야 합니다.

```swift
@State private var drag = CGSize.zero

Text("제주에서 온 엽서")
    .padding(40)
    .background(.cyan.opacity(0.2))
    .offset(drag)
    .gesture(DragGesture()
        .onChanged { drag = $0.translation }
        .onEnded { _ in withAnimation(.spring) { drag = .zero } })
```

코드는 원문 예제를 옮기지 않고 엽서 넘기기 상황에 맞춰 새로 작성했습니다. 저장된 원본과 계산되는 값, 동작 뒤 바뀌는 값을 구분해 보세요.

### gesture 종료 뒤 spring으로 카드 원위치시키기

손을 놓은 시점의 상태 변경만 withAnimation으로 감싸면 손가락을 따를 때는 즉각 반응하고 복귀할 때만 탄성이 생깁니다. 값이 없거나 형식이 틀리거나 범위를 벗어난 경우도 살핍니다. 임의의 기본값이나 강제 언래핑은 실제 원인을 숨길 수 있습니다. 화면 상태는 최소로 저장하고 나머지는 원본에서 계산해야 모순을 예방할 수 있습니다.

리뷰할 때는 값의 소유자, 변경 사건, 실패 뒤 표시를 질문하세요. 오늘의 엽서 넘기기 예제에서는 transition으로 뷰 삽입과 제거의 움직임 정하는 과정이 그 접점입니다. 입력 타입과 출력 타입을 말로 이어 보면 판단 기준을 재사용할 수 있습니다.
