## 핵심 개념 해설

### List와 ForEach로 제출 단어를 행으로 표시하기

List는 제출 배열이 바뀔 때 식별 가능한 문자열 행만 갱신하고 플랫폼다운 스크롤과 구분선을 제공합니다. 값이 만들어지는 지점, 수정 권한을 가진 코드, 최종 소비자를 순서대로 표시해 보세요. 여행지 단어 놀이처럼 익숙한 소재를 사용하면 문법보다 데이터 역할에 집중할 수 있습니다. 컴파일 성공이 도메인 규칙까지 보장하지는 않으므로 경계 입력도 함께 대입해야 합니다.

```swift
@State private var usedWords = [String]()
let rootWord = "transportation"

List(usedWords, id: \.self) { word in
    Label(word, systemImage: "character.book.closed")
}
// 앱에 반드시 포함될 파일이라면 Bundle URL 실패를 fatalError로 알립니다.
```

코드는 원문 예제를 옮기지 않고 여행지 단어 놀이 상황에 맞춰 새로 작성했습니다. 저장된 원본과 계산되는 값, 동작 뒤 바뀌는 값을 구분해 보세요.

### 번들 텍스트 파일을 URL과 String으로 읽기

fatalError는 사용자가 틀린 입력을 했을 때가 아니라 개발자가 포함하기로 약속한 리소스가 빠진 복구 불가능한 구성 오류에 씁니다. 값이 없거나 형식이 틀리거나 범위를 벗어난 경우도 살핍니다. 임의의 기본값이나 강제 언래핑은 실제 원인을 숨길 수 있습니다. 화면 상태는 최소로 저장하고 나머지는 원본에서 계산해야 모순을 예방할 수 있습니다.

리뷰할 때는 값의 소유자, 변경 사건, 실패 뒤 표시를 질문하세요. 오늘의 여행지 단어 놀이 예제에서는 필수 리소스 누락을 fatalError로 개발 중 드러내기이 그 접점입니다. 입력 타입과 출력 타입을 말로 이어 보면 판단 기준을 재사용할 수 있습니다.
