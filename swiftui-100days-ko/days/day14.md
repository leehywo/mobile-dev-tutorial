## 핵심 개념 해설

### nil로 예약 메모가 없음을 정확히 표현하기

옵셔널은 빈 문자열과 메모가 아예 없는 상태를 구분해 데이터의 실제 가능성을 타입에 기록합니다. 값이 만들어지는 지점, 수정 권한을 가진 코드, 최종 소비자를 순서대로 표시해 보세요. 숙소 예약처럼 익숙한 소재를 사용하면 문법보다 데이터 역할에 집중할 수 있습니다. 컴파일 성공이 도메인 규칙까지 보장하지는 않으므로 경계 입력도 함께 대입해야 합니다.

```swift
let note: String? = nil
let room: String? = "502호"
let message = note ?? "요청 사항 없음"
if let first = room?.first {
    print("객실 표기 시작: \(first)")
}
print(message)
```

코드는 원문 예제를 옮기지 않고 숙소 예약 상황에 맞춰 새로 작성했습니다. 저장된 원본과 계산되는 값, 동작 뒤 바뀌는 값을 구분해 보세요.

### if let과 guard let로 옵셔널을 안전하게 풀기

옵셔널 체이닝은 room이 nil이면 first 접근도 nil로 끝내므로 강제 언래핑으로 인한 충돌을 피합니다. 값이 없거나 형식이 틀리거나 범위를 벗어난 경우도 살핍니다. 임의의 기본값이나 강제 언래핑은 실제 원인을 숨길 수 있습니다. 화면 상태는 최소로 저장하고 나머지는 원본에서 계산해야 모순을 예방할 수 있습니다.

리뷰할 때는 값의 소유자, 변경 사건, 실패 뒤 표시를 질문하세요. 오늘의 숙소 예약 예제에서는 nil 병합과 옵셔널 체이닝으로 대체 흐름 만들기이 그 접점입니다. 입력 타입과 출력 타입을 말로 이어 보면 판단 기준을 재사용할 수 있습니다.
