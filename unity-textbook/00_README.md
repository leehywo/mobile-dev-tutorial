# Unity 인디 게임 개발 교과서

> [Unity 기초 트랙](../react-to-unity.md)을 끝낸 사람을 위한 **읽고, 따라 치고, 풀어보는 교과서**입니다.
> [로드맵](../unity-indie-roadmap.md)이 "무엇을 배워야 하는가"의 지도라면, 이 교과서는 그 길을 실제로 걷는 책입니다.

## 이 책의 방식

- **게임 하나를 30장 동안 키웁니다.** (5부 31~40장은 먹고살기 위해 필요한 보강으로, 첫 출시 경로 사이에 끼워 읽습니다.) 기초 트랙 STEP 4의 "코인 먹기"를 출발점으로, 장마다 기능을 더해
  마지막에는 Steam·모바일에 올릴 수 있는 2D 서바이버라이크 **「코인 러시(Coin Rush)」**가 됩니다.
- 모든 장은 같은 틀입니다 — **학습 목표 → 왜 필요한가 → 개념 → 실습 → 흔한 실수 → 연습 문제 → 셀프 체크 → 요약**.
- 코드는 **Unity 6 (6000.x) + URP 2D** 기준입니다. React/JS를 알던 사람에게 도움이 되는 곳엔 비교를 붙였습니다.
- 기술만이 아니라 **게임 디자인·수익화·마케팅·사업**까지 같은 방식으로 "실습"합니다 —
  스프레드시트를 만들고, 스토어 페이지를 쓰고, 출시 계획서를 작성합니다.

## 코인 러시 — 최종 모습

```
장르: 2D 탑다운 서바이버라이크 (뱀파이어 서바이버즈류, 1판 10분)
조작: 이동만 (공격은 자동) — 키보드/게임패드/모바일 가상 조이스틱
루프: 적 웨이브를 피하며 → 적이 떨군 코인·경험치 수집 → 레벨업 시 업그레이드 3택1
메타: 판이 끝나면 코인으로 영구 강화·캐릭터 해금
훅:   코인은 경험치이자 화폐 — 판 안 제단에서 쓸까, 판 밖 영구 강화를 위해 모을까
수익: 1차 출시는 Steam 유료판. 모바일 무료판(보상형 광고 + IAP)은 확장 트랙(25·37장)
```

## 공부 방법

### 첫 출시 경로 (권장)

기술 20장을 다 끝내고 나서야 기획을 시작하면 재미 검증과 첫 공개가 너무 늦어집니다. 아래 순서로 **작게 출시하면서 필요한 기술을 배우세요.**

읽는 규칙은 두 가지입니다.

- **`→` 순서는 각 장 머리의 선수 장을 지킵니다.** 같은 칸의 `·` 는 순서를 바꿔도 됩니다.
- **괄호 안에 절·단계가 적힌 장은 그 부분만 읽습니다.** 나머지는 뒤 단계에서 다시 나오거나, 아래 '확장' 줄로 갑니다.

| 단계 | 읽을 장 | 끝났다는 증거 |
|---|---|---|
| 0. 시작 전 | 34(1~3단계) → 33(1~3단계: Git 절) | 생활비·가용 시간 예산, 저장소 |
| 1. 작은 게임 완성 | 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 | 게임잼 또는 짧은 게임 공개 |
| 2. 차별점 검증 | 35(1~6단계) → 21 → 24(개념 절 중 '플레이테스트의 종류'~'테스트 배포 채널'만) | 플레이 영상·관찰 기록·제작 승인 문서 |
| 3. 첫 상업작 제작 | 09 → 10 → 11 → 12 → 31 · 32 → 13 → 14 → 16 → 17 → 18 → 19(1·2·4·5단계) → 22 → 23 → 24(나머지 전체) | 최종 품질의 짧은 구간, 한/영 빌드, 5인 플레이테스트 보고서 |
| 4. 출시 준비 | 33(4~6·8·9단계) → 38 → 25(개념의 '수익 모델별 설계 원칙'·'코인 러시의 수익 전략' + 2단계 래퍼 패턴만) → 26 → 27 → 28 → 36 | 스토어 페이지, QA 매트릭스, 행정 체크리스트 |
| 5. 출시와 운영 | 29 → 34(4~7단계, 매월) → 30 → 39 | 공개 출시·30일 운영·정산·회고 |
| 6. 두 번째 작품과 24개월 검증 | 40 (35 게이트·36 지원금 절·39 운영 계획을 다시 사용) | 서로 다른 상품 가설의 출시 URL 2개, 24개월 현금흐름·시간 기록, 24개월 종료 판정 문서 |
| 확장 (필요할 때) | 19(3단계 원격 콘텐츠·6단계 GitHub Actions) · 33(7단계 CI 테스트) · 20 · 15 | 해당 기능이 실제로 필요해진 시점의 결과물 |
| 모바일 확장 | 25(나머지 실습) → 37 | 실기기 테스트 구매·광고 보상 |

경로를 이렇게 짠 이유입니다.

- **24장**의 선수 장은 10·22·23입니다. 그래서 2단계에서는 코드가 필요 없는 관찰·설문 절만 읽고 21장 그레이박스 테스트에 쓰며, 이벤트 로그·집계 도구 실습은 23장 뒤에 합니다.
- **22장**은 19장의 `StageLoader`·`EnemySpawner`를 이어받고, **19장**은 18장을 선수로 둡니다. 그래서 18 → 19 → 22 순서입니다. 19장 4단계 빌드 메뉴는 5단계 용량 리포트를 호출하므로 둘을 함께 합니다. 26·38장도 이 빌드 스크립트를 쓰고, 32장 체크리스트의 '빌드에서 언어 전환 확인' 항목은 19장을 마친 뒤 확인합니다.
- **Addressables·빌드 자동화·에디터 툴**은 [로드맵](../unity-indie-roadmap.md) PART J에서 첫 출시 뒤 **3단계(수익 구조 학습)**에 있는 항목입니다. 교과서 코드가 이어지는 19장의 기본 로더·빌드 메뉴(1·2·4·5단계)만 경로에 남기고, 원격 콘텐츠·GitHub Actions(19장 3·6단계)·CI 테스트(33장 7단계)·20장 에디터 툴은 첫 출시의 필수 조건이 아니므로 확장으로 뺐습니다. 익숙한 도구 작업이 시장 검증 시간을 밀어내지 않게 하려는 배치입니다. 20장을 건너뛰면 22장의 웨이브 데이터는 Inspector에서 직접 입력하고(22장 본문이 이 경우를 안내합니다), 31장 3단계의 임포트 규칙 교체 대신 텍스처 설정을 Inspector에서 맞춥니다.
- **26·28장**은 25장을 선수로 적지만, 1차 출시인 Steam 유료판에 필요한 것은 25장의 수익 모델 판단과 얇은 래퍼 패턴입니다. 광고·IAP 구현은 모바일 확장에서 합니다.
- **1부(01~08)** 는 장마다 앞 장의 코드를 이어받으므로(예: 03장은 02장, 07장은 06장이 선수) 건너뛰지 않습니다.

15장(HLSL)과 17장의 Timeline·보스 컷신은 필요해질 때 보는 선택 과목입니다.

### 공부 요령

- 1부는 순서대로 하세요. 2~4부는 필요한 장부터 골라 봐도 됩니다 (각 장 머리에 선수 장이 적혀 있습니다).
- 코드는 복사하지 말고 **직접 치세요.** 오타를 고치는 시간이 곧 학습입니다.
- 연습 문제의 해설은 접혀 있습니다. **먼저 풀고** 펼치세요.
- Claude 등 AI에게 물어볼 때는 "이 장의 셀프 체크 문항을 내가 설명해볼 테니 틀린 곳을 지적해줘"가 가장 효과적입니다.
