## 핵심 개념 해설

### 폼 상태와 파생 결과의 연결을 세 프로젝트에서 비교하기

복습의 핵심은 문법 목록을 다시 외우는 것이 아니라 상태 변경이 어느 body 계산과 결과 표시를 다시 만드는지 설명하는 일입니다. 값이 만들어지는 지점, 수정 권한을 가진 코드, 최종 소비자를 순서대로 표시해 보세요. 여행 예약 요약처럼 익숙한 소재를 사용하면 문법보다 데이터 역할에 집중할 수 있습니다. 컴파일 성공이 도메인 규칙까지 보장하지는 않으므로 경계 입력도 함께 대입해야 합니다.

```swift
struct BookingSummary: View {
    let city: String
    let guests: Int
    var body: some View {
        VStack(alignment: .leading) {
            Text(city).font(.headline)
            Text("\(guests)명").foregroundStyle(.secondary)
        }
        .padding()
    }
}
```

코드는 원문 예제를 옮기지 않고 여행 예약 요약 상황에 맞춰 새로 작성했습니다. 저장된 원본과 계산되는 값, 동작 뒤 바뀌는 값을 구분해 보세요.

### 스택·alert·수정자 순서를 코드 리뷰 관점으로 복기하기

요약 뷰는 도시와 인원을 값으로 받을 뿐 편집하지 않으므로 @State를 추가하지 않고 부모의 소유권을 존중합니다. 값이 없거나 형식이 틀리거나 범위를 벗어난 경우도 살핍니다. 임의의 기본값이나 강제 언래핑은 실제 원인을 숨길 수 있습니다. 화면 상태는 최소로 저장하고 나머지는 원본에서 계산해야 모순을 예방할 수 있습니다.

리뷰할 때는 값의 소유자, 변경 사건, 실패 뒤 표시를 질문하세요. 오늘의 여행 예약 요약 예제에서는 재사용 뷰로 중복을 줄이되 데이터 소유권은 부모에 남기기이 그 접점입니다. 입력 타입과 출력 타입을 말로 이어 보면 판단 기준을 재사용할 수 있습니다.
